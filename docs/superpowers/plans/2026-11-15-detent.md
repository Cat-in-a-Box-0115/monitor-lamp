# Detent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Monitor Lamp into Detent:
- a new minimal tray popup and window;
- now playing and synced lyrics;
- PC stats;
- a USB data link to the knob, which uses the knob's lamp changes as manual changes.

**Architecture:**
- **Library crate (`src/lib.rs`):** the platform-neutral logic (protocol, LRC, Afterburner parser, settings
  migration). It is unit-tested on the Mac with `cargo test --lib`.
- **Windows-only modules (`#[cfg(windows)]`):** media (SMTC), stats reader, serial link. They sit beside the
  existing app.
- **Companion thread:** collects the state and pushes changes to the link.

**Tech Stack:**
- Rust 2021 and Slint 1 with the software renderer (existing).
- New crates:
  - `windows` 0.58, adding the features `Media_Control`, `Foundation`, `Storage_Streams` and
    `Win32_System_Memory`.
  - `serialport` 4, `ureq` 2 (rustls), and `image` 0.25 (jpeg, png).

**Spec:** `docs/superpowers/specs/2026-11-15-desk-companion-design.md`

## Global Constraints

- **Name:** Detent. The exe is `Detent.exe`, settings are in `%APPDATA%\Detent\settings.json`, and the log is
  `%APPDATA%\Detent\detent.log`.
- **Look:**
  - Ground `#0E0E0E`, text `#E8E5DE`, muted `#6A6762`, lines `#242321` (1 px).
  - Off tile `#151514`, on tile `#1F1E1C`.
  - JetBrains Mono everywhere, embedded.
  - No icons, outlined boxes, progress bars or hint text.
- **The app never shows** CPU, GPU or RAM figures; they go to the knob only.
- **Memory:** about 40 MB, 0% CPU when idle. The software renderer only.
- **No regressions** in on-at-sign-in, off at sign-out, shutdown or sleep, screen sync, flows or time of day.
- **Protocol:** v1.
  - Each frame is `type u8, len u16 LE, payload`, COBS-encoded and ended by `0x00`.
  - USB VID `0x303A`, PID `0x8D01`.
- **Secrets:** the Wi-Fi password is never saved. No secrets in the repo, logs or hub.

## Review Focus

1. **Songs with no lyrics, instrumentals, or LRCLIB down or slow.** The knob should get `LYRICS_NONE` quickly, and
   the app must never block. → test `lyrics_none_when_no_synced` (Task 3). The fetch runs on its own thread with a
   5 s timeout.
2. **Afterburner not running, or only some sensors enabled** (no CPU temperature). Missing values are sent as
   missing; nothing crashes. → test `mahm_missing_entries` (Task 4).
3. **Seeking, pausing, and songs repeating or changing with the same title.** The lyric line should follow the
   position, and `line_id` should change whenever the line changes. → test `lrc_seek_back_and_repeat` (Task 3).
4. **The knob is unplugged or replugged mid-song, or the COM port disappears.** The link reconnects, then re-sends
   `HELLO`, the full now-playing, the cover and the lyrics. → test `link_resends_snapshot_on_reconnect` (Task 6).
5. **Upgrading from Monitor Lamp.** The old settings are moved over, the old Run key and exe are removed, and the
   lamp still turns on at the next sign-in. → test `migrate_copies_old_settings_once` (Task 1), plus an
   `install.ps1` check on the PC (Task 9).

### Task 2: Protocol

**Files:**
- Create: `src/protocol.rs`
- Create: `docs/knob-protocol.md`, the shared reference for the knob repo. It lists the message IDs, field layouts,
  VID/PID and the reconnect rules.

**Interfaces (produces):**
```rust
pub const VID: u16 = 0x303A; pub const PID: u16 = 0x8D01; pub const PROTO_VER: u8 = 1;
pub enum Msg {
  Hello { proto: u8, version: String, caps: u32 },                       // 0x01 both ways
  NowPlaying { playing: bool, pos_ms: u32, dur_ms: u32, title: String, artist: String }, // 0x10
  Cover { art_id: u32, w: u16, h: u16, chunk: u16, chunks: u16, data: Vec<u8> },        // 0x11 RGB565 LE
  Lyrics { line_id: u32, prev: String, cur: String, next: String },     // 0x12
  LyricsNone,                                                            // 0x13
  PcStats { cpu_pct: Option<u8>, cpu_c: Option<u8>, gpu_pct: Option<u8>, gpu_c: Option<u8>, ram_pct: Option<u8>, host: String }, // 0x14, 0xFF = missing
  Provision { ssid: String, pass: String, lamp_ip: String, lamp_token: String }, // 0x20
  Time { unix: u32, tz_min: i16 },                                       // 0x21
  LampState { power: bool, bright: u8, ct: u16, bg_power: bool, bg_rgb: u32 }, // 0x30 knob->app
  Log(String),                                                           // 0x31 knob->app
}
pub fn encode(m: &Msg) -> Vec<u8>;            // COBS frame incl. trailing 0x00
pub struct Decoder { .. } impl Decoder { pub fn push(&mut self, bytes: &[u8]) -> Vec<Msg>; }
pub fn cover_chunks(art_id: u32, w: u16, h: u16, rgb565: &[u8]) -> Vec<Msg>; // 1024-byte chunks
```

- **Strings:** a `u8` length followed by UTF-8, truncated on a char boundary to the knob's buffer sizes:
  - title 39, artist 31;
  - lyrics prev/next 63, cur 95;
  - ssid 32, pass 64, ip 15, token 32;
  - host 23.

- [ ] Tests:
  - `roundtrip_every_msg`: encode, then decode, gives the same value for one of each variant.
  - `decoder_handles_split_and_joined_frames`: two frames fed one byte at a time, and three frames in one push.
  - `decoder_skips_garbage`: random bytes before a valid frame still give that frame; a bad length is dropped.
  - `strings_truncate_on_char_boundary`: a 50-char CJK title becomes 39 bytes or fewer and is valid UTF-8.
  - `cover_chunks_reassemble`: 180×180×2 bytes gives 64 chunks, concatenated equal to the input.
- [ ] FAIL, then implement, then PASS. Commit.

### Task 3: Synced lyrics

**Files:**
- Create: `src/lrc.rs` (neutral)
- Create: `src/lyrics.rs` (cfg windows; LRCLIB fetch and disk cache in `%APPDATA%\Detent\lyrics\`)

**Interfaces (produces):**
```rust
pub struct Lrc { pub lines: Vec<(u32 /*ms*/, String)> }
pub fn parse(text: &str) -> Option<Lrc>;      // None if no timed lines
impl Lrc { pub fn at(&self, pos_ms: u32) -> Option<(u32 /*line index = line_id*/, &str, &str, &str)>; }
// lyrics.rs
pub fn fetch(title: &str, artist: &str, dur_s: u32) -> Option<Lrc>; // GET https://lrclib.net/api/get?track_name&artist_name&duration, fallback /api/search; uses syncedLyrics only
```

- `line_id` is `index + 1` so that 0 means "before the first line".
- Blank lyric lines (instrumental gaps) are kept as `""`.
- Multiple timestamps on one line (`[00:12.00][01:30.00]text`) are expanded.
- `[offset:+/-ms]` is applied.

  - `lrc_seek_back_and_repeat`: going forward, then back to an earlier time, returns the earlier `line_id`.
  - `at_before_first_line`: returns `(0, "", "", first)`.

### Task 4: PC stats

**Files:**
- Create: `src/mahm.rs`, a neutral parser.
- Create: `src/stats.rs` (cfg windows):
  - `OpenFileMappingW("MAHMSharedMemory")` read-only;
  - CPU % from `GetSystemTimes` deltas;
  - RAM % from `GlobalMemoryStatusEx.dwMemoryLoad`;
  - host from `GetComputerNameW`.

**Interfaces (produces):**
```rust
pub struct Mahm { pub gpu_c: Option<f32>, pub gpu_pct: Option<f32>, pub cpu_c: Option<f32> }
pub fn parse(buf: &[u8]) -> Option<Mahm>;   // None if signature != 'MAHM' (0x4D48414D LE) or sizes inconsistent
// stats.rs
pub fn sample() -> detent::protocol::Msg;   // Msg::PcStats
```

- **Layout:** the header is `signature, version, header_size, num_entries, entry_size` (u32 each). Entries start at
  `header_size`, with stride `entry_size`.
- **Each entry:** five 260-byte name strings (`src_name` is at offset 0), then `data: f32` at offset 1300.
- **Matching names:**
  - `"GPU temperature"` and `"GPU usage"`: take the first GPU.
  - `"CPU temperature"`: if it's missing, use the max of `"CPU<n> temperature"`.
- `data` equal to `f32::MAX`, or not finite, counts as missing.

- [ ] Tests:
  - `mahm_parses_synthetic_buffer`
  - `mahm_missing_entries` (only GPU temperature present, so the CPU values are `None`)
  - `mahm_cpu_core_fallback`
  - `mahm_rejects_bad_signature_and_truncation`
- [ ] FAIL, then implement, then PASS. Commit.

### Task 5: Now playing (SMTC)

**Files:** Create `src/media.rs` (cfg windows).

**Interfaces (produces):**
```rust
pub struct Media { pub playing: bool, pub title: String, pub artist: String, pub pos_ms: u32, pub dur_ms: u32,
                   pub at: std::time::Instant /*when pos_ms was read*/, pub art_id: u32,
                   pub art_rgba42: Option<Vec<u8>> /*84x84 for the popup*/, pub art_rgb565: Option<Vec<u8>> /*180x180 for the knob*/ }
pub fn start(on_change: impl Fn(Option<Media>) + Send + 'static); // own thread; event-driven via GlobalSystemMediaTransportControlsSessionManager
pub fn key(k: MediaKey); pub enum MediaKey { PlayPause, Next, Prev }  // TryTogglePlayPauseAsync etc. on the current session
```

- Subscribe to `CurrentSessionChanged`, `MediaPropertiesChanged`, `PlaybackInfoChanged` and
  `TimelinePropertiesChanged`, plus a 1 s resync while playing.
- `art_id` is a hash of title, artist and thumbnail bytes.
- The thumbnail is decoded with `image`, center-cropped square, and resized with Triangle filtering.
- **Verification is manual on the PC (Task 9):** Melodia and YouTube in Edge both show title, artist and cover, and
  pause updates within 1 s.
- [ ] Compiles for the Windows target. Commit.

### Task 6: Knob link

**Files:**
- Create: `src/link.rs`. Its core is generic over `Read + Write`, so it's tested on the Mac.
- Create: `tools/fake_knob.py`. It uses pyserial; given a COM port it sends `HELLO` and a `LAMP_STATE` every 5 s, and
  prints decoded frames.

**Interfaces:**
- Consumes: `protocol::{encode, Decoder, Msg, cover_chunks, VID, PID}`.
- Produces:
  ```rust
  pub struct Snapshot { pub now: Option<Msg /*NowPlaying*/>, pub cover: Option<(u32, Vec<u8>)>, pub lyrics: Msg, pub stats: Option<Msg> }
  pub struct Session<T: Read + Write> { .. }
  impl<T> Session<T> { pub fn new(io: T, snap: &Snapshot) -> Self /*sends Hello + full snapshot*/;
                       pub fn send(&mut self, m: &Msg) -> io::Result<()>; pub fn poll(&mut self) -> io::Result<Vec<Msg>>; }
  #[cfg(windows)] pub fn run(state: Arc<Mutex<Snapshot>>, rx: Receiver<Msg>, on_msg: impl Fn(Msg) + Send + 'static, on_conn: impl Fn(bool) + Send + 'static);
  ```
- `run` scans `serialport::available_ports()` every 2 s for a USB port matching VID/PID, at 115200 baud
  (ignored by CDC), with a 50 ms read timeout. On any I/O error it drops the session and rescans.
- A cover is sent only when its `art_id` differs from the last one sent in this session.

- [ ] Tests (in-memory duplex):
  - `session_sends_hello_then_snapshot`
  - `link_resends_snapshot_on_reconnect`: a new `Session` sends the full snapshot again, including the cover.
  - `same_art_id_not_resent`
  - `poll_returns_lamp_state`
- [ ] FAIL, then implement, then PASS. Commit.

### Task 7: Companion wiring

**Files:**
- Create: `src/companion.rs` (cfg windows)
- Modify: `src/main.rs` to start it, and add `fn on_knob_lamp(s: LampState)`.

**Behaviour:**
- **Media changes:** update the Snapshot and send `NowPlaying` (and `Cover` when the art changed).
- **Lyrics:**
  - When the track changes, start a lyrics fetch on its own thread.
  - Every 200 ms while playing, compute `lrc.at(pos_ms + elapsed)` and send `Lyrics` when `line_id` changes.
  - Send `LyricsNone` when there are no lyrics.
- **Stats:** every 2 s, sample `stats::sample()` and send it.
- **Time:** send `Time` on connect.
- **Knob `LampState`:** treated as a manual change.
  - A brightness or ct change calls the same path as a manual change in the app (`touched()`, which pauses time of
    day as today).
  - A `bg_rgb` or `bg_power` change stops screen sync and the flow.
  - Then update the shown state.
- **Provision:** sent from the window's "Set up knob" button. The ssid and pass come from text fields that are
  cleared after sending; `lamp_ip` and `token` come from settings.

- [ ] Compiles for the Windows target. On the PC with `fake_knob.py` over a com0com pair: frames arrive, and a
  `LAMP_STATE` with a new brightness stops time of day. Commit.
